# Portable-VirtualBox · модернизация 2026 года

[English](README.md) · [Возможности](https://github.com/zlocorp/Portable-VirtualBox/blob/dev/modernization-2026/FEATURES.md) · [История изменений](https://github.com/zlocorp/Portable-VirtualBox/blob/dev/modernization-2026/CHANGELOG.md)

Модернизация [vboxme/Portable-VirtualBox](https://github.com/vboxme/Portable-VirtualBox): двуязычная оболочка, проверяемые зависимости и переносимые пользовательские данные.

> **Экспериментальная сборка, ещё не готовый повседневный лаунчер ВМ.** При обычном двойном клике запуск ВМ и установка драйверов отключены. Отдельная тестовая ALPHA и CI уже используют настоящий Oracle Manager: в изолированной Windows Server проверены загрузка Alpine Linux x86-64, запись на VDI и безопасная очистка драйвера. Настоящий UAC и системные операции на Windows 10/11 ещё не прошли приёмку.

**Минимальный релиз:** русский интерфейс и одна локальная ВМ. [Условия релиза и оставшиеся проверки Windows 10/11](docs/RELEASE-GATES.md), [границы безопасности](docs/SECURITY-MODEL.md). Проверки системных операций выполняются только в изолированной одноразовой среде, не на основной ОС.

**Первый запуск без установленного Python.** Нажмите «Подготовить VirtualBox / папки»: **«Да»** скачает официальный VirtualBox 7.2.22 по HTTPS, **«Нет»** позволяет выбрать скачанный файл. Отдельный `Portable-VirtualBox-Setup.exe` проверяет встроенный SHA-256 и подготавливает `app64` без запуска MSI или установки драйверов. Существующая `app64` не перезаписывается. Команды: `--download-app64` и `--prepare-app64 "ПУТЬ_К_УСТАНОВЩИКУ"`. [Проверка Windows](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/40209800549) подтвердила оба варианта.

При скачивании показываются полученные МиБ (и процент, если сервер передал длину файла), затем отдельные этапы проверки SHA-256 и извлечения. Прогресс информационный, готовность определяется проверенными файлами `app64`, а не индикатором.

**Поддерживаемые хосты:** Oracle VirtualBox 7.2 предназначен в том числе для клиентских Windows 10/11 x64. Проверка совместимости лаунчера принимает Windows 10 начиная со сборки **19041** и Windows 11; серверные редакции, ARM64 и неизвестное состояние отклоняются. Это пока не подтверждение реального Start/Stop на этих ОС.

**Перенос ВМ со снимками:** на одноразовых Windows-хостах проверены 4 варианта: перенос папки или смена буквы тестового диска `P:` -> `Q:`, с заранее снятой регистрацией или с устаревшей записью `VirtualBox.xml`. После регистрации по новому адресу сохранились UUID ВМ, UUID снимка, SHA-256 базового и разностного VDI; посторонних служб/процессов не осталось. [Результаты Windows CI](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/40462477639). В экспериментальном окне Manager добавлено отдельное исправление регистрации с выбором проверенной копии и явным подтверждением. Обычный аудит остается только для чтения.

**Тестовая ALPHA:** отдельный нерелизный пакет для изолированной Windows
10/11 x64 запускается с флагом `Portable-VirtualBox.exe --alpha-runtime`.
Он использует основной EXE и отдельный helper с проверкой SHA-256 сборки,
запрашивает UAC только для системных операций. Обычный двойной клик и
стандартный диагностический ZIP ничего не устанавливают. Это пока
**не прошедшая испытания Windows 11** сборка, не применять на основной
системе. [Правила тестирования](docs/ALPHA-WINDOWS-TEST.md).

## Что изменилось относительно оригинала

**Резервное копирование и восстановление в новую папку.** В обычном интерфейсе доступны создание и проверка офлайн-копии всей папки `data/` с проверкой SHA-256, отменой и сохранением незавершённого этапа `.pending` без перезаписи существующей копии. Пока работают процессы или службы VirtualBox, копирование блокируется. **Восстановление создаёт отдельный новый каталог, не перезаписывая существующий профиль. Это копия файлов из `data/`, не снимок работающей ВМ**: внешние диски и носители в неё не входят.

**Подготовка к исправлению регистрации после переноса:** команда `Portable-VirtualBox.exe --plan-vm-rebind` показывает, какому новому файлу ВМ соответствует старая запись `VirtualBox.xml`. Если найден ровно один совпадающий UUID, старый файл отсутствует, все диски и снимки локальные, а службы и процессы VirtualBox остановлены, команда `--prepare-vm-rebind "НОВАЯ_ПАПКА_КОПИИ"` делает резервную копию всего `data/` с проверкой SHA-256. Чужие ВМ, внешние диски, неполные снимки и символьные ссылки блокируют подготовку. **Эти CLI-команды не меняют регистрацию, XML или драйверы.**

**Несколько перенесенных ВМ, только проверка.** В обычном GUI кнопка **«Проверить переносимость ВМ»** теперь тоже показывает этот отчет, включая при смене языка или обновлении. Она не выполняет массовое исправление регистрации.  Команда `Portable-VirtualBox.exe --plan-multi-vm-rebind` показывает предварительный отчет для **2–16** машин, перенесенных из одного прежнего каталога, если прежний путь отсутствует. Проверяются UUID каждой ВМ, старые и новые пути, файлы дисков и снимков, дополнительные файлы, сохраненные состояния, контрольные суммы и отсутствие активности VirtualBox. Код **0 означает только возможность прочитать отчет, а не разрешение исправления**; 2 - подходящих нескольких ВМ нет, 3 - данные небезопасны или неизвестны, 64 - неверные аргументы. Команда ничего не регистрирует, не удаляет и не копирует. Исходные файлы и независимую проверенную резервную копию надо сохранить. `--prepare-vm-rebind` и кнопка ALPHA **«Исправить регистрацию ВМ» по-прежнему работают строго с одной ВМ**. Массовое исправление, физический перенос между ПК и восстановление после произвольного обрыва не проверены.

**Проверенная копия нескольких ВМ.** После успешного отчёта `--plan-multi-vm-rebind` можно выполнить `Portable-VirtualBox.exe --prepare-multi-vm-rebind "НОВАЯ_ПАПКА_КОПИИ"`. Команда создаёт **новую полную офлайн-копию `data/` с SHA-256**, не перезаписывая существующие файлы. Используется уже проверенный механизм копирования; затем повторно сверяются SHA-256 реестра, конфигурации всех ВМ, список носителей и отсутствие активности VirtualBox. Статус `BACKUP_ONLY` и код 0 означают **только готовую проверенную копию, не разрешение исправления регистраций**. Код 2 - операция заблокирована или подходящих нескольких ВМ нет; 3 - результат копирования не подтверждён; 64 - неверные аргументы. При ошибке готовую или промежуточную папку `.pending` сохраняем для проверки, ничего не удаляем. Команда не запускает Oracle, не меняет XML и не требует повышения прав.

**Проверка восстановления нескольких ВМ после частичного сбоя.** Команда `Portable-VirtualBox.exe --review-multi-vm-rebind "ИСХОДНАЯ_ПРОВЕРЕННАЯ_КОПИЯ"` сверяет исходный полный SHA-256 бэкап с текущим реестром и всеми файлами ВМ. Для каждого UUID она показывает `STALE` (старая запись), `ABSENT` (записи нет) или `LOCAL` (правильный новый путь). Возможный следующий шаг выводится **только как подсказка, не команда**. Если все ВМ уже зарегистрированы правильно, результат `COMPLETE` не предлагает повторной операции. Чужие и дублирующиеся регистрации, изменения дисков или снимков, повреждённый бэкап, наличие старого исходного файла и работающий VirtualBox приводят к отказу. Код 0 означает только корректный отчёт, 3 - запрет, 64 - неверные аргументы. **Никакого автоматического unregister/register эта команда не выполняет.** Обычное исправление одной ВМ осталось неизменным.

**Проверка шагов восстановления пока только для чтения.** Нативные тесты Windows подтверждают строгий порядок UUID, неизменность SHA-256 файлов .vbox, изменение SHA-256 реестра после каждого шага и запрет пропуска, повтора или перестановки операций. Частичная последовательность не считается завершенной. Это **не защищенный журнал транзакции** и не разрешение запускать массовое исправление регистраций. Для включения нужны отдельный контроллер с проверкой владельца, восстановление после прерывания и приемка UAC на Windows 10/11.

Для существующих действий helper `Prepare`/`Finish`/`Recover` добавлен отдельный защищённый журнал с принудительным сбросом на диск: намерение перед запуском worker, его подтверждённый выход и завершение проверок helper фиксируются отдельно. Неполная запись остаётся свидетельством неопределённого результата. Это ещё не журнал шагов нескольких ВМ и не разрешение автоматически повторять операции после сбоя.

**Явное исправление в ALPHA:** для одной выключенной ВМ с локальными дисками и снимками откройте окно Manager и нажмите **«Исправить регистрацию ВМ»**. Выберите исходную проверенную копию, созданную до изменения регистрации, проверьте показанные UUID, старый и новый пути, папку копии и подтвердите действие. Контроллер повторно проверит именно эти данные перед подготовкой драйверов и выполнит Oracle `unregistervm` без `--delete`, затем `registervm`. Отмена выбора или ответ «Нет» сохраняют регистрацию и системные ресурсы. Обычный двойной клик остается диагностическим режимом.

Если операция прервалась после снятия регистрации, сохраните исходную копию. Сначала завершите необходимое **«Восстановление после сбоя»**, чтобы не осталось прежнего контроллера, работающих ВМ или незавершенной сессии драйверов. Затем повторно выберите ту же копию в **«Исправить регистрацию ВМ»**. Пустой реестр допускается только при подтверждении исходного UUID и совпадении файлов ВМ с копией; в этом случае выполняется **только регистрация**. Уже исправленная запись изменений не требует. Неоднозначность или изменение данных блокируют действие, резервная копия не перезаписывается. Перенос сохраненного состояния, исправление нескольких ВМ и произвольное отключение питания пока не приняты. Актуальные результаты Windows-проверок собраны в [Draft PR #7](https://github.com/zlocorp/Portable-VirtualBox/pull/7); Windows Server CI не подтверждает безопасность интерактивной Windows 10/11.

**Проверка переносимости ВМ перед копированием.** В обычном GUI есть «Проверить переносимость ВМ», в CLI команда `--audit-vms`. Она читает `.vbox`, считает снимки, показывает внешние/отсутствующие диски и проверяет реестр `data/.VirtualBox/VirtualBox.xml`. Зарегистрированные вне переносимой папки машины и незарегистрированные локальные конфигурации отмечаются для проверки. При риске неполной копии GUI требует подтверждения, CLI выводит предупреждение. **Копируются только файлы `data`, внешние диски не включаются**. Проверка не меняет XML и не гарантирует полноту резервной копии.

**Новая русско-английская оболочка.** Язык можно переключить, явно сохранить кнопкой «Запомнить язык» и вернуть выбор по Windows. Настройка переживает перезапуск и перенос папки. Временный `--lang` её не перезаписывает. Диагностика копируется, причины отказа читаемы, окно «О программе» содержит только краткие сведения о продукте.

**Русская локализация проверена в изолированном Windows CI.** Причины отказа сессии и исправления регистрации получают русское пояснение с сохранением точного технического кода. Подсказки и результат копирования обновляются при переключении RU/EN, длинные подписи кнопок допускают перенос строки. Имена служб, поля JSON, внутренние состояния и исходные сообщения Oracle не переводятся и не меняют контракт диагностики.

**Язык менеджера Oracle.** Явно сохраненный язык лаунчера (`ru` или `en`) применяется при следующем полном запуске подготовленной сессии через штатный `VBoxManage setextradata global GUI/LanguageID`, с обычными правами и проверкой результата. Для английского используется встроенный язык Oracle `C`. Режим `auto`, отсутствующая/поврежденная настройка и временный `--lang` не перезаписывают отдельный выбор Oracle. Повторное открытие менеджера при работающей ВМ также не меняет язык. Наш код не переписывает XML вручную. Подготовка и проверка app64 требуют непустые `nls/VirtualBox_ru.qm` и `nls/qt_ru.qm` из того же закрепленного пакета Oracle, без отдельного стороннего русификатора.

На `3301638` [скомпилированный лаунчер](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/41537264954) прошел переключение RU -> EN -> RU, измерение размеров подписей и проверку отсутствия записи данных; все три снимка окна просмотрены. [Сквозной тест Oracle и Alpine](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/41537257180) подтвердил русский первый запуск, русское повторное открытие с работающей ВМ и английский второй запуск по реальным подписям меню и кнопок, а не только настройке языка. Снимки Oracle просмотрены; чтение записанных гостем байтов VDI, снимки ВМ, исправление регистрации и очистка также прошли. На снимках остается предупреждение Oracle об опросе USB: поддержка USB-проброса отложена. Это не приемка всех DPI или интерактивного UAC на Windows 10/11. Язык системных диалогов зависит от Windows; полноту перевода внутри Oracle определяет его пакет.

**Состояния служб для диагностики и тестов.** `--diagnose-services` выводит тот же русско-английский отчет по десяти службам, что и GUI; `--diagnose-services-json` возвращает независимую от языка схему 1 (`services`, `exit_code`). Строка JSON содержит только `name`, `observation`, `state`, `win32_error`, `ownership`. Запуск, остановка, возобновление и переход к паузе теперь видны в диагностическом снимке; строгие проверки запуска и очистки по-прежнему требуют двух совпадающих стабильных наблюдений. Только ошибка 1060 при открытии означает отсутствие службы; отказ в доступе и неопределенность не скрываются. Для неотсутствующих служб владение остается `UNVERIFIED`. Пути к образам и учетные записи не выводятся. Нет запуска COM, создания профиля или системных операций. Код 0 означает известные наблюдения, **не готовность хоста и не разрешение очистки**; 4 означает неопределенность, 64 означает неверные аргументы.

**Портативный Oracle CLI в ALPHA.** Связанные со сборкой `VBoxManage.cmd` и `VBoxManagePortable.exe` используют `data\.VirtualBox` этого каталога и проверенную защищенную копию Oracle, без перехода к установленному VirtualBox. Сначала запустите сессию ALPHA через Manager, затем вызывайте команды из терминала без повышения прав. Проверяются живой контроллер и защищенная сессия; блокировка команды согласована с очисткой. До подготовки, во время очистки и после завершения сессии команды запрещены. Сохраняются аргументы, рабочий каталог и код завершения Oracle. Это не защита от любых изменений ВМ: команды Oracle могут менять данные, хотя `unregistervm --delete` явно запрещен. В обычном диагностическом ZIP адаптера нет. Подробности в [инструкции ALPHA](docs/ALPHA-WINDOWS-TEST.md).

**Без устаревших бинарников.** Из активного дерева удалены старые AutoIt, 7za, DevCon, SnetCfg, четырнадцать старых INI-переводов и заставка. Для сборки используется официальный внешний AutoIt **3.3.18.0**, для тестов зафиксирован Oracle **VirtualBox 7.2.22 r175245**. Дистрибутив проверяется по хешу и подписи, файлы извлекаются из MSI/CAB без скрытого запуска установщика.

**Проверяется не один EXE.** Оболочка называет отсутствующие или пустые обязательные EXE, DLL и файлы VBoxSup. Отдельно сообщает о недостающих папках, недоступных путях, ссылках и конфликтах с системной установкой. Наличие файлов не выдаётся за проверку подписи или разрешение запуска ВМ.

**Переносимые данные без переписывания чужих настроек.** Явная подготовка создаёт `data/.VirtualBox`, `data/Machines` и `logs`, сохраняя существующие файлы. Язык хранится в `data/launcher.ini`. Повреждённый или чужой файл не перезаписывается; новая настройка записывается через промежуточный файл в той же папке. Эти функции не редактируют Oracle XML.

**Окно Manager не равно работающей ВМ.** В отчёте раздельно показаны процессы Manager, GUI/headless-процессы ВМ и фоновые процессы. Это снимок наблюдений, а не подтверждение состояния гостевой ОС и не основание для остановки или удаления служб.

## Что можно использовать сейчас

Откройте EXE для GUI либо выполните:

```powershell
Portable-VirtualBox.exe --lang ru --help
Portable-VirtualBox.exe --save-language ru
Portable-VirtualBox.exe --save-language auto
Portable-VirtualBox.exe --prepare-profile
Portable-VirtualBox.exe --download-app64
Portable-VirtualBox.exe --prepare-app64 "D:\Downloads\VirtualBox-7.2.22-175245-Win.exe"
Portable-VirtualBox.exe --app-status
Portable-VirtualBox.exe --check-readiness
Portable-VirtualBox.exe --diagnose
Portable-VirtualBox.exe --diagnose-services
Portable-VirtualBox.exe --diagnose-services-json
Portable-VirtualBox.exe --audit-vms
Portable-VirtualBox.exe --plan-vm-rebind
Portable-VirtualBox.exe --plan-multi-vm-rebind
Portable-VirtualBox.exe --prepare-multi-vm-rebind "D:\Backups\Moved-VMs-original"
Portable-VirtualBox.exe --review-multi-vm-rebind "D:\Backups\Moved-VMs-original"
Portable-VirtualBox.exe --prepare-vm-rebind "D:\Backups\Moved-VM-original"
Portable-VirtualBox.exe --about
Portable-VirtualBox.exe --backup-data "D:\Backups\PortableVBox-2026-10-22"
Portable-VirtualBox.exe --verify-backup "D:\Backups\PortableVBox-2026-10-22"
Portable-VirtualBox.exe --restore-backup "D:\Backups\PortableVBox-2026-10-22" "E:\Restored-VBox-Data"
```

`--save-language ru|en|auto` явно создаёт папки данных, если их ещё нет. Команды просмотра сами их не создают. `--app-status` возвращает 0 при наличии обязательных непустых файлов, 2 при отсутствии `app64`, 3 при неполном или небезопасном наборе. `--check-readiness` возвращает 3 при блокирующей причине либо 2, если проверки пройдены, но запуск отключён в этой сборке. Ни один код не включает запуск ВМ.

Код `--audit-vms`: **0** при отсутствии обнаруженных проблем, **2** при необходимости проверки или отсутствии ВМ, **3** при небезопасном XML/пути. Даже код 0 не гарантирует целостность всей ВМ.

Если `launcher.ini` повреждён, файл сохраняется, используется язык Windows. Оставшийся `launcher.ini.pending` требует осмотра перед удалением: это может быть след прерванной записи. Не распаковывайте предварительную сборку поверх рабочей установки VirtualBox.

Расширенный аудит ВМ проверен на [скомпилированной RU/EN-оболочке и резервном копировании](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39793670380), [23 нативных тестовых программах AutoIt](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39793670330) и [реальной регистрации ВМ Oracle 7.2.22 после запуска и очистки драйвера](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39793670384). Проверки выполнялись на изолированной Windows Server, **не на интерактивной Windows 11**.

## Интеграция с Manager: экспериментальная сборка

**Восстановление после прерванной подготовки драйверов (эксперимент):** Защищённые контрольные точки позволяют очистить только собственные ресурсы после установки VBoxSup, после его запуска или после регистрации VBoxSDS, даже если обычная квитанция готовой сессии не появилась. [Независимые Windows CI-сценарии](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39778793621) подтвердили восстановление на трёх этапах и отказ при живом владельце, отсутствии квитанции, повторном запросе или подделанной записи VBoxSup/VBoxSDS. При отказе службы не трогаются. Если операция оборвалась *до* записи контрольной точки, автоматическая очистка блокируется. Это пока не пользовательская функция и не проверка интерактивного UAC/Windows 11.

**Восстановление заброшенной сессии (пока эксперимент):** отдельный тестовый GUI получил явную кнопку восстановления. Helper сверяет защищённые квитанции прежнего запуска, проверяет, что старый контроллер больше не работает, нет активных ВМ и все службы принадлежат именно этой сессии. Затем разрешается однократная очистка собственного VBoxSup/VBoxSDS и защищённых файлов. [Проверка на одноразовой Windows](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39761908190) подтвердила отказ при живом контроллере/ВМ и сохранение конфигурации ВМ после очистки. Автоматического удаления нет. Это **не** проверка реального UAC в Windows 11, перезагрузки, отключения питания или произвольного обрыва внутри системной операции и не возможность обычного релиза.

В основном лаунчере работают кнопки **«Запустить VirtualBox», «Завершить сессию» и «Открыть менеджер»**: на одноразовом CI-хосте либо при явном `--alpha-runtime` с парным helper на изолированной рабочей станции. [Проверка настоящего GUI на Windows](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39567202279) подтвердила запуск Oracle Manager, сохранение работающей пустой ВМ после его закрытия, повторное открытие Manager, отказ второго экземпляра и две очистки с сохранением UUID ВМ. Обычный диагностический ZIP системные операции не включает. Поздние проверки helper запускают Manager и ВМ с обычным токеном; интерактивные подтверждение и отмена UAC на Windows 10/11 еще требуют приемки. [Отчёт и границы проверки](https://github.com/zlocorp/Portable-VirtualBox/blob/dev/modernization-2026/docs/EXECUTION-2026-10-21-manager-session.md).

## Готовность и проверки

Копия создаётся отдельной папкой `data/` с манифестом `SHA256SUMS.txt`. Отмена или сбой оставляют промежуточную папку `.pending`, но не портят исходные файлы. Хеши обнаруживают повреждения, однако манифест не подписан. Восстановление файлов в новую папку реализовано, но там нет лаунчера или Oracle app64: их нужно установить отдельно. Исправление регистрации одной перенесенной ВМ и восстановление собственных системных ресурсов выполняются отдельными подтверждаемыми действиями ALPHA; внешние диски и произвольные повреждения автоматически не восстанавливаются.


[FEATURES.md](https://github.com/zlocorp/Portable-VirtualBox/blob/dev/modernization-2026/FEATURES.md) отделяет **доступные пользователю функции**, **эксперименты CI** и **планы**. [CHANGELOG.md](https://github.com/zlocorp/Portable-VirtualBox/blob/dev/modernization-2026/CHANGELOG.md) ведётся в разделе **Unreleased**: опубликованных версий модернизации пока нет.

Код пакета адаптаций `183f35da` прошёл [сборку x64, проверки обычного скомпилированного CLI и ZIP](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39548219426), [18 нативных тестовых программ AutoIt](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39548219415) и [запуск пустой ВМ с очисткой собственных ресурсов](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39548214487). Готовый ZIP скачан и проверен отдельно: контрольная сумма совпадает, оба README и сведения об авторах действительно включены. [Подробный отчёт и границы проверки](https://github.com/zlocorp/Portable-VirtualBox/blob/dev/modernization-2026/docs/EXECUTION-2026-10-21-community-adoption.md).

**Пока не готово:** пользовательский Start/Stop Manager на Windows 11 с подтверждённым UAC, проверенный привилегированный helper с UAC, полноценная миграция, восстановление после отключения питания/обрыва внутри драйверной операции и обновление Oracle с откатом, дополнительные USB/сетевые драйверы. Запуск Alpine Linux x86-64 с реальной записью на VDI проверен отдельно в [Windows CI #40407596523](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/40407596523), но это не заменяет интерактивную приёмку UAC, Windows 11 и масштабирования интерфейса.
