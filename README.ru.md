# Portable-VirtualBox · модернизация 2026 года

[English](README.md) · [Возможности](https://github.com/zlocorp/Portable-VirtualBox/blob/dev/modernization-2026/FEATURES.md) · [История изменений](https://github.com/zlocorp/Portable-VirtualBox/blob/dev/modernization-2026/CHANGELOG.md)

Модернизация [vboxme/Portable-VirtualBox](https://github.com/vboxme/Portable-VirtualBox): двуязычная оболочка, проверяемые зависимости и переносимые пользовательские данные.

> **Предварительная диагностическая сборка, пока не готовый лаунчер ВМ.** Обычный интерфейс не запускает VirtualBox Manager и виртуальные машины и не устанавливает драйверы. Реальные эксперименты с драйвером и пустой ВМ выполняются только на одноразовых Windows-хостах CI. Приёмка Windows 11 с обычной учётной записью и UAC ещё впереди.

## Что изменилось относительно оригинала

**Резервное копирование и восстановление в новую папку.** В обычном интерфейсе доступны создание и проверка офлайн-копии всей папки `data/` с проверкой SHA-256, отменой и сохранением незавершённого этапа `.pending` без перезаписи существующей копии. Пока работают процессы или службы VirtualBox, копирование блокируется. **Восстановление создаёт отдельный новый каталог, не перезаписывая существующий профиль. Это копия файлов из `data/`, не снимок работающей ВМ**: внешние диски и носители в неё не входят.

**Проверка переносимости ВМ перед копированием.** В обычном GUI есть «Проверить переносимость ВМ», в CLI команда `--audit-vms`. Она читает `.vbox`, считает снимки, показывает внешние/отсутствующие диски и проверяет реестр `data/.VirtualBox/VirtualBox.xml`. Зарегистрированные вне переносимой папки машины и незарегистрированные локальные конфигурации отмечаются для проверки. При риске неполной копии GUI требует подтверждения, CLI выводит предупреждение. **Копируются только файлы `data`, внешние диски не включаются**. Проверка не меняет XML и не гарантирует полноту резервной копии.

**Новая русско-английская оболочка.** Язык можно переключить, явно сохранить кнопкой «Запомнить язык» и вернуть выбор по Windows. Настройка переживает перезапуск и перенос папки. Временный `--lang` её не перезаписывает. Диагностика копируется, причины отказа читаемы, окно «О программе» содержит только краткие сведения о продукте.

**Без устаревших бинарников.** Из активного дерева удалены старые AutoIt, 7za, DevCon, SnetCfg, четырнадцать старых INI-переводов и заставка. Для сборки используется официальный внешний AutoIt **3.3.18.0**, для тестов зафиксирован Oracle **VirtualBox 7.2.22 r175245**. Дистрибутив проверяется по хешу и подписи, файлы извлекаются из MSI/CAB без скрытого запуска установщика.

**Проверяется не один EXE.** Оболочка называет отсутствующие или пустые обязательные EXE, DLL и файлы VBoxSup. Отдельно сообщает о недостающих папках, недоступных путях, ссылках и конфликтах с системной установкой. Наличие файлов не выдаётся за проверку подписи или разрешение запуска ВМ.

**Переносимые данные без переписывания чужих настроек.** Явная подготовка создаёт `data/.VirtualBox`, `data/Machines` и `logs`, сохраняя существующие файлы. Язык хранится в `data/launcher.ini`. Повреждённый или чужой файл не перезаписывается; новая настройка записывается через промежуточный файл в той же папке. Эти функции не редактируют Oracle XML.

**Окно Manager не равно работающей ВМ.** В отчёте раздельно показаны процессы Manager, GUI/headless-процессы ВМ и фоновые процессы. Это снимок наблюдений, а не подтверждение состояния гостевой ОС и не основание для остановки или удаления служб.

## Что можно использовать сейчас

Откройте EXE для GUI либо выполните:

```powershell
Portable-VirtualBox.exe --lang ru --help
Portable-VirtualBox.exe --save-language ru
Portable-VirtualBox.exe --save-language auto
Portable-VirtualBox.exe --prepare-profile
Portable-VirtualBox.exe --app-status
Portable-VirtualBox.exe --check-readiness
Portable-VirtualBox.exe --diagnose
Portable-VirtualBox.exe --audit-vms
Portable-VirtualBox.exe --about
Portable-VirtualBox.exe --backup-data "D:\Backups\PortableVBox-2026-10-22"
Portable-VirtualBox.exe --verify-backup "D:\Backups\PortableVBox-2026-10-22"
Portable-VirtualBox.exe --restore-backup "D:\Backups\PortableVBox-2026-10-22" "E:\Restored-VBox-Data"
```

`--save-language ru|en|auto` явно создаёт папки данных, если их ещё нет. Команды просмотра сами их не создают. `--app-status` возвращает 0 при наличии обязательных непустых файлов, 2 при отсутствии `app64`, 3 при неполном или небезопасном наборе. `--check-readiness` возвращает 3 при блокирующей причине либо 2, если проверки пройдены, но запуск отключён в этой сборке. Ни один код не включает запуск ВМ.

Код `--audit-vms`: **0** при отсутствии обнаруженных проблем, **2** при необходимости проверки или отсутствии ВМ, **3** при небезопасном XML/пути. Даже код 0 не гарантирует целостность всей ВМ.

Если `launcher.ini` повреждён, файл сохраняется, используется язык Windows. Оставшийся `launcher.ini.pending` требует осмотра перед удалением: это может быть след прерванной записи. Не распаковывайте предварительную сборку поверх рабочей установки VirtualBox.

## Интеграция с Manager: экспериментальная сборка

**Восстановление после прерванной подготовки драйверов (эксперимент):** Защищённые контрольные точки позволяют очистить только собственные ресурсы после установки VBoxSup, после его запуска или после регистрации VBoxSDS, даже если обычная квитанция готовой сессии не появилась. [Независимые Windows CI-сценарии](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39778793621) подтвердили восстановление на трёх этапах и отказ при живом владельце, отсутствии квитанции, повторном запросе или подделанной записи VBoxSup/VBoxSDS. При отказе службы не трогаются. Если операция оборвалась *до* записи контрольной точки, автоматическая очистка блокируется. Это пока не пользовательская функция и не проверка интерактивного UAC/Windows 11.

**Восстановление заброшенной сессии (пока эксперимент):** отдельный тестовый GUI получил явную кнопку восстановления. Helper сверяет защищённые квитанции прежнего запуска, проверяет, что старый контроллер больше не работает, нет активных ВМ и все службы принадлежат именно этой сессии. Затем разрешается однократная очистка собственного VBoxSup/VBoxSDS и защищённых файлов. [Проверка на одноразовой Windows](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39761908190) подтвердила отказ при живом контроллере/ВМ и сохранение конфигурации ВМ после очистки. Автоматического удаления нет. Это **не** проверка реального UAC в Windows 11, перезагрузки, отключения питания или произвольного обрыва внутри системной операции и не возможность обычного релиза.

В отдельной тестовой программе уже работают кнопки **«Запустить VirtualBox», «Завершить сессию» и «Открыть Manager»**. [Проверка настоящего GUI на Windows](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39567202279) подтвердила запуск Oracle Manager, сохранение работающей пустой ВМ после его закрытия, повторное открытие Manager, отказ второго экземпляра и две очистки с сохранением UUID ВМ. **В обычный диагностический ZIP эта программа не включена:** системные операции пока требуют уже повышенных прав на одноразовом хосте, а не готового перехода через UAC. [Отчёт и границы проверки](https://github.com/zlocorp/Portable-VirtualBox/blob/dev/modernization-2026/docs/EXECUTION-2026-10-21-manager-session.md).

## Готовность и проверки

Копия создаётся отдельной папкой `data/` с манифестом `SHA256SUMS.txt`. Отмена или сбой оставляют промежуточную папку `.pending`, но не портят исходные файлы. Хеши обнаруживают повреждения, однако манифест не подписан. Восстановление файлов в новую папку реализовано, но там нет лаунчера или Oracle app64: их нужно установить отдельно. Автоматическое восстановление регистрации ВМ, внешних дисков и системных драйверов не реализовано.


[FEATURES.md](https://github.com/zlocorp/Portable-VirtualBox/blob/dev/modernization-2026/FEATURES.md) отделяет **доступные пользователю функции**, **эксперименты CI** и **планы**. [CHANGELOG.md](https://github.com/zlocorp/Portable-VirtualBox/blob/dev/modernization-2026/CHANGELOG.md) ведётся в разделе **Unreleased**: опубликованных версий модернизации пока нет.

Код пакета адаптаций `183f35da` прошёл [сборку x64, проверки обычного скомпилированного CLI и ZIP](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39548219426), [18 нативных тестовых программ AutoIt](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39548219415) и [запуск пустой ВМ с очисткой собственных ресурсов](https://github.com/zlocorp/Portable-VirtualBox/actions/runs/39548214487). Готовый ZIP скачан и проверен отдельно: контрольная сумма совпадает, оба README и сведения об авторах действительно включены. [Подробный отчёт и границы проверки](https://github.com/zlocorp/Portable-VirtualBox/blob/dev/modernization-2026/docs/EXECUTION-2026-10-21-community-adoption.md).

**Пока не готово:** обычный Start/Stop Manager, проверенный привилегированный helper с UAC, полноценная миграция, восстановление после отключения питания/обрыва внутри драйверной операции и обновление Oracle с откатом, дополнительные USB/сетевые драйверы. Не заявляем запуск гостевой ОС с диском или визуальную приёмку Windows 11 и масштабирования. Успех теста на Windows Server не подменяет эту приёмку.
