## Deliverable

Prepare a new app64 tree from the pinned, signed Oracle 7.2.20 wrapper on an isolated Windows runner. Use MSI tables for file layout and cabinet membership, not guessed paths or `msiexec /a`. The prepared files are not an installed or tested hypervisor. Keep launcher startup disabled.

## Tasks

1. Inspect actual File, Component, Directory and Media tables in read-only mode. Record metadata only. Verify current baseline (35 Python tests).
2. Write failing offline regressions for directory resolution, component joins, media sequences, cabinet/file identity, unsafe filenames, collisions, missing bytes and existing destinations. Implement a bounded pure layout planner and exclusive staged-file assembly.
3. Implement Windows read-only MSI access and cabinet-only file expansion. Handle embedded and external cabinets; never invoke MSI actions or CustomAction tables. Check native failures and keep the private staging tree unpublished on any failure.
4. Run the entire workflow on the actual pinned Oracle package: signature/hash, extraction, MSI identity, application tree completeness, required PE architecture, per-file hashes, input hashes and unchanged VBox service registry snapshot. Verify output, update PR/report and leave startup disabled.

## Design decisions

- Windows Installer databases are opened with MSIDBOPEN_READONLY. Only known SELECT queries and stream reads are allowed.
- Only descendants of the verified application root are staged; directories for shortcuts/system destinations are not mapped into Windows.
- File table identifiers map cabinet entries to destination names. Media LastSequence ranges determine cabinet membership. Target long filenames are preserved.
- Cabinet extraction writes only validated filenames into a private newly-created staging directory. Existing app64/user VM trees are never updated in place.
- Supported input is the pinned Oracle package family, not arbitrary MSI compatibility. Unknown schemas, package identity, compression modes or spanning-cabinet dependencies fail closed.
- File preparation does not evaluate install conditions, register COM, create services, or claim Windows 11/VM acceptance. Conditional application payloads may be prepared without being activated.
- Trusted user-selected parent directory is required; no claim of resisting an administrator or same-account attacker mutating directory topology concurrently.
